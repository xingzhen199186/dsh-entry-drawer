# dsh-entry-drawer（侧栏入口收纳）

把 DSH 左侧栏入口列表的第一行变成开关：点一下，其余入口整块收起，会话历史随之向上；再点一下还原。

版本 0.1.0 · MIT · 面向 DSH 0.2.x 的 Web / 桌面端客户端插件

## 为什么需要它

DSH 左侧栏上半部分是一个「入口列表」：插件、插件市场、自动化任务、远程窗口、任务看板、记忆系统……每个插件都往这里加一行。装的东西一多，列表就往下压会话历史。

平台给第三方的位置只有 `sidebar.panellist`（侧栏的面板列表座位）。槽位（slot）：界面上一个固定的位置，插件只能往里放自己的东西，改不了别人放的。这些行的盒子、行高、点击行为都由壳层掌管（壳层：DSH 自己的界面框架，插件代码跑在它里面），而且平台没有提供「把入口收成一组」的能力。

插件因此不新增任何功能，只借一个座位做一件事：在列表最前面放一行，用它收起其余行。

## 界面与用法

展开时（默认）：

- 位置：左侧栏入口列表的第一行。
- 内容：一对朝上的双箭头，加文字「入口收纳」。
- 下方是原有的全部入口。

点这一行：

- 其余入口整块隐藏（直接不占位置，不是变灰）。
- 会话历史上移。
- 箭头翻成朝下，这一行留在原位。

再点一次，全部入口回来，箭头朝上。

偏好存在两处：`localStorage`（localStorage：浏览器给网页的一小块存储，关掉页面也还在）的 `dsh-entry-drawer:collapsed`，以及一个同名 cookie。之所以多存一份 cookie，是因为桌面端每次启动会在 `127.0.0.1` 上换一个端口，而浏览器把 `localStorage` 按「协议 + 主机 + 端口」分开存放；cookie 只认主机、不认端口，所以跨重启记住状态靠它。重载页面或重启桌面端，都保持上次的选择。

## 安装

前提：DSH 0.2.x，Node.js 与 pnpm 可用（`dsh plugin` 只是 pnpm 的转发器）。

**方式一：从 GitHub 安装**

```sh
dsh plugin --profile <name> add github:xingzhen199186/dsh-entry-drawer
```

`<name>` 换成你的 profile 名，例如 `web` 或 `desktop`。

**方式二：从本地目录安装**

```sh
dsh plugin --profile <name> add ./dsh-entry-drawer
```

也可以在插件管理器里选「从目录安装」，指向这个文件夹。

装完之后重载窗口；桌面端建议直接重启应用。客户端半（`client.js`，跑在浏览器里的那一半）要等窗口重新加载才会挂上，桌面端默认没有客户端热更新。

本项目没有发布到 npm（`package.json` 里 `private: true`），所以不能用 npm 包名安装。

卸载：

```sh
dsh plugin --profile <name> remove dsh-entry-drawer
```

## 它怎么工作

一共三件事：占一个座位、拦一次点击、写一条样式规则。另有一个保险面板。

**1. 占座位**

客户端半在加载时注册两次：

```js
ctx.slots.register({ name: 'sidebar.panellist', id: 'entry-drawer', order: -1000, label })
ctx.slots.register({ name: 'main', key: 'entry-drawer' })
```

`order: -1000` 让它排在入口列表最前面。行里画出来的东西就是开关本身：一个 `span.dsh-entry-drawer-mark` 包着双箭头图标。标签「入口收纳」来自插件自带的中英词典。

**2. 拦点击**

行盒子和行点击都归壳层所有，插件改不了。于是在 `document` 上挂一个捕获阶段的 click 监听（捕获阶段：事件从最外层往里传的那一段，比壳层自己的处理更早看到这次点击）。判据很窄——点到的元素在 `button` 里，且那个 `button` 含 `.dsh-entry-drawer-mark` 标记。命中就 `preventDefault()` 加 `stopPropagation()`，壳层「切换到某个面板」的逻辑不会执行，插件改成翻转收起状态并写入偏好。

监听只注册一个，随插件效果一起挂上和回收。点侧栏别处不受影响。

**3. 写样式**

收起状态不改 DOM，由插件自己的一条 `<style>` 表达。展开时这条样式只含开关图标的基础样式；收起时追加一条：

```css
nav[aria-label="全局面板"] > *:not(:has(.dsh-entry-drawer-mark)) { display:none !important }
```

读法：在无障碍名为「全局面板」的导航里（`aria-label`：给读屏软件和自动化工具用的名字，DSH 用它标记这块导航），隐藏所有不含本插件标记的直接子项。

导航名优先从活的语言词典取（`sidebar` 命名空间的 `panels.label`），取不到时用两个已知名字「全局面板」和「Global panels」，各自生成一条规则，所以中英文界面都能命中。名字来自词典，做过程序内的转义，不会被拼成奇怪的 CSS。切换界面语言时样式重算。

**4. 保险面板**

除了列表行，插件还在 `main`（主内容区）注册了一个同 id 的占位面板，渲染结果为空。正常路径用不到它，因为点击已被拦下。但如果哪条旁路仍然选中了这个面板，它会在挂载时翻转收起状态，然后 `ctx.layout.selectPanel(...)` 跳回你上一个看过的面板（没有可回的就去空面板），而不是因为面板内容不存在而报错。

**5. 记住选择**

每次切换都同时写 `localStorage` 和一个同名 cookie。前者是同一个地址内的快速读取，后者用来跨桌面端的端口变化——详见上面「界面与用法」里的说明。

**宿主半（`index.js`）** 是空实现：`apply()` 里什么都不做。留着它，是为了让这个包在插件树里有一个可选中、可检查、可卸载的入口。所有逻辑都在客户端。

## 兼容性与已知限制

下面写的都是实际情况，不是免责声明。

- **依赖导航的无障碍名。** 样式规则靠 `nav[aria-label="全局面板"]` 定位。上游哪天改掉这个名字、或者不再用 `nav` 元素，插件会安静地失效——只是收起失败，不会误藏别的东西。修法是改客户端里的 `KNOWN_NAV_LABELS`。
- **点击拦截在 React 之外。** 它靠「`button` 里含本插件标记」这个结构判断。上游若改了行结构（行不再是 `button`，或标记被移出按钮），拦截会退化：点击落回壳层、选中这一个面板。保险面板会兜住并跳回原面板，但你的体感是「点了没反应」，不是「收起」。
- **收起是整组隐藏。** 官方的「插件」「自动化任务」「更多」也一起消失，因为它们和第三方入口同在一个列表里。展开即恢复。做不到只藏第三方、留下官方。
- **窄侧栏下没有可收的东西。** Windows 桌面端把侧栏收成窄条时，整块入口列表本来就是隐藏的，插件不改变任何东西。
- **本地目录安装有脆弱点。** 用 `add ./目录` 装时，profile 里记的是这个目录的路径。之后移动或删除该文件夹，客户端半会加载失败。要长期用，改用 git 安装，或者别动这个目录。
- **只在 Web / 桌面端测过。** `dsh.client` 声明 `platform: "web"`，并依赖 `@deepseek-ai/dsh-client-ui-sidebar`（提供侧栏座位的那一节客户端）。没有侧栏的形态（例如 headless）不会加载它。
- **状态按浏览器存。** 换浏览器、换主机名（例如从 `127.0.0.1` 换成 `localhost`）、清掉站点数据，都会回到「展开」。多个窗口共用同一份存储，但插件不监听 `storage` 事件，所以一个窗口切换后，另一个窗口要重载才跟上。

## 开发与测试

没有构建步骤，纯 JS。客户端半是 `window.__ModuleLoader__.load({ id, factory })` 形式的模块；宿主半是普通 ESM，导出一个空的 `apply()`。

测试不需要浏览器，用 Node 内置的 `assert`、一个极小的假 React 与假 DOM 直接驱动 `client.js`：

```sh
node test/client.test.mjs
```

通过时输出 `client.test.mjs: all checks passed`。

覆盖：两个座位的注册契约、展开与收起两种样式表、点击拦截（阻止壳层、翻转、写入偏好）、点别处不受影响、活词典优先、标签转义、无词典与无存储时的降级、样式表和监听器的归属与回收。
